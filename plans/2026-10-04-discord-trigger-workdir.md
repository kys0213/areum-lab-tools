# discord 메시지 트리거 — 채널별 작업 디렉토리(cwd)

> **Plan — 이 시점의 결정 기록.** 현재 정책의 신뢰 소스가 아니다.
> 날짜: 2026-10-04 · 브랜치: epic/discord-connector · 이슈: 없음 · 승인 출처: 사용자 승인 (Claude 플러그인 세션의 계약 변경 요청을 사용자가 수용)

## 왜

- 앞선 계획(`plans/2026-10-04-discord-connector-cli.md`)에서는 채널→작업 디렉토리 매핑을 Claude 플러그인 설정에 두기로 했다.
- 플러그인 세션이 사용자와 합의해 이 매핑을 discord CLI 설정으로 옮기자고 요청했고, 사용자가 수용했다. 채널 관련 설정(이슈 채널 목록 등)을 CLI 한곳에 모으고, 플러그인은 설정 파일 없이 Claude 실행만 맡기 위해서다.
- CLI 입장에서는 "`on_message` 명령을 어느 디렉토리에서 실행하나"라는 범용 기능이라 CLI가 Claude를 모른다는 경계는 유지된다.
- 런처는 스레드를 시작할 때 실제로 쓴 디렉토리를 기록했다가 `--resume` 때 같은 디렉토리를 쓴다. Claude 세션은 실행 디렉토리 기준으로 저장되므로 디렉토리가 바뀌면 이어가기가 깨진다. 그래서 stdin JSON에 실제 적용한 `cwd`가 필요하다.

## 결정

- 설정(`~/.areum/discord/config.json`)에 두 필드를 추가한다.
  - `workdirs`: `{ "<채널 ID 또는 channels 별칭>": "<디렉토리>" }`. 키는 `issue_channels`와 같은 방식으로 별칭을 풀어 채널 ID로 바꾼다.
  - `default_workdir`: 매핑이 없는 채널에 쓰는 디렉토리.
- 경로 규칙: 절대경로이거나 `~/`로 시작해야 한다(`~/`는 홈 디렉토리로 펼친다). 상대경로는 데몬 시작 시 Config 오류로 거부한다.
- `on_message`가 설정됐는데 `workdirs`와 `default_workdir`가 모두 비어 있으면 데몬 시작 시 Config 오류로 거부한다. 어떤 메시지도 실행할 수 없는 설정을 조용히 받아들이지 않기 위해서다. 이 기능은 아직 릴리스 전이라 기존 사용자 영향이 없다.
- 디렉토리 결정(발행할 메시지로 판정된 뒤):
  - 스레드 안 메시지는 `parent_channel_id`, 최상위 메시지는 `channel_id`로 `workdirs`를 찾는다.
  - 없으면 `default_workdir`를 쓴다. 매핑에서 찾은 디렉토리가 실제로 없을 때는 기본값으로 대신하지 않는다.
  - 결정된 디렉토리가 없거나 디렉토리가 아니면 실행하지 않고 데몬 stderr에 로그를 남긴다. Discord에는 아무것도 쓰지 않는다.
  - 존재 여부는 발행 시점마다 확인한다(데몬 실행 중 디렉토리가 지워질 수 있다).
- 실행: `on_message`를 결정된 디렉토리를 현재 디렉토리로 해서 실행한다.
- stdin JSON에 `cwd`(실제 적용한 디렉토리의 정규화된 절대경로, 문자열)를 추가한다. 다른 필드는 그대로다.

## 버린 선택지

- 매핑 실패 시 기본 디렉토리로 대체: 엉뚱한 저장소에서 작업이 실행될 수 있다.
- 매핑을 플러그인 설정에 유지: 플러그인 세션과 사용자가 바꾸기로 합의했다.
- 디렉토리 없음을 스레드에 알리기: CLI의 메시지 감지 경로는 Discord에 쓰지 않는다는 경계를 지킨다.
- 시작 시점에만 디렉토리 존재 확인: 실행 중 삭제를 놓친다.
