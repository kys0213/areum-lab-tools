# doppel P1b — 브리프와 수락률

> **Plan — 이 시점의 결정 기록.** 현재 정책의 신뢰 소스가 아니다.
> 날짜: 2026-10-21 · 브랜치: epic/doppel · 이슈: 없음 · 승인 출처: 사용자 승인 (전체 설계 `kys0213/kys-claude-plugin` `plans/2026-10-21-doppel.md` 의 결정 3·5·11, 진행은 "자율주행해줘")

## 왜

P1a 로 질문이 doppel inbox 에 모인다. P1b 는 각 질문에 배경과 판례 기반 추천을 붙이고, 추천과 내 답의 일치를 쌓아 "얼마나 나를 닮았나" 를 잰다.

## 결정 사항

- **판단은 plugin skill, 실행은 데몬.** 데몬은 판례 검색 번들(결정적)을 만들어 설정된 명령의 stdin 으로 넘기고, 결과 JSON 을 검증해 저장한다. 기본 명령은 `claude -p --output-format json --model sonnet /doppel:brief` 이고, 브리프의 내용은 `plugins/doppel/skills/brief` 가 정한다. headless 에서 slash 로 plugin skill 을 부르고 stdin 번들을 읽는 것은 2026-10-21 확인했다.
- **기본은 끈다.** 질문마다 모델 호출이 하나 더 든다. `doppel daemon run --brief` (또는 `--brief-command`) 로 켠다.
- **브리프 세션은 doppel 에 붙지 않는다.** 데몬이 띄우는 명령에 `DOPPEL_DISABLE=1` 을 넣고, plugin 은 그 env 가 있으면 아무것도 하지 않는다 — 브리프 세션의 질문이 다시 브리프를 부르는 고리를 끊는다. 부모의 `CLAUDE_CODE_SESSION_ID` 는 지운다 (중첩 실행이 부모 id 를 이어받는 것을 P1a 에서 봤다).
- **출력 계약은 JSON 객체 하나.** 코드 펜스(```json) 한 겹은 벗긴다 — 모델 출력의 흔한 형태라서다. 그 밖의 모양, 번들에 없는 판례 인용, 질문에 맞지 않는 추천은 `failed` 로 남긴다 (조용히 버리지 않는다).
- **기록**: 브리프마다 사용한 판례 id 목록과 명령 문자열(프롬프트 버전의 대리값)을 남긴다.
- **수락**: ask 가 확정(`close`)될 때 최종 답이 추천과 같으면 수락이다. 추천 없이 새 의견만 낸 브리프는 수락 판정에서 뺀다.
- **`doppel stats`** 는 데몬 없이 DB 를 읽는다. 전체와 카테고리별(질문이 원장에서 분류된 경우) 수락률을 낸다. baseline 대비 lift 는 카테고리 분류가 쌓인 뒤 더한다.

## 버린 선택지

- **브리프 프롬프트를 데몬에 내장** — 판단 내용이 결정적 도구로 들어간다 (CLAUDE.md 책임 경계).
- **기본으로 켬** — 데몬을 띄우기만 해도 질문마다 비용이 생긴다.
- **출력에서 JSON 을 아무 데서나 찾아 쓰기** — 계약 위반을 숨긴다.
- **원장 `decisions` 에 추천 열 추가** — 기존 DB 이관이 필요하다. 브리프는 `briefs` 테이블에 두고 ask 로 잇는다.

## 범위 밖

터미널 band 에 브리프 표시, 추천을 뒤집은 사례의 골든 후보 자동 등록(분류가 먼저 필요하다), doppel 이 세션을 띄우는 런처.
