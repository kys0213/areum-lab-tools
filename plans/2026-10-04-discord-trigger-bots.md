# discord 메시지 트리거 — 봇 메시지 허용 목록(`trigger_bots`)

> **Plan — 이 시점의 결정 기록.** 현재 정책의 신뢰 소스가 아니다.
> 날짜: 2026-10-04 · 브랜치: epic/discord-connector · 이슈: 없음 · 승인 출처: 사용자 승인

## 왜

- Claude 플러그인 세션과 E2E를 자율로 돌리려면 트리거 메시지를 자동으로 만들어야 한다.
- 지금 데몬 필터는 봇이 쓴 메시지(자기 자신 포함)를 모두 무시한다. 런처가 결과를 `discord send`로 올릴 때 그 메시지가 다시 트리거되는 루프를 막기 위해서다.
- 그래서 같은 봇 토큰으로 `discord send`해도 트리거가 일어나지 않는다. 사용자는 사람이 직접 올리는 대신 CLI를 고치는 쪽을 골랐다.

## 결정

- 설정(`~/.areum/discord/config.json`)에 `trigger_bots: ["<봇 user ID>", ...]`를 추가한다. 기본값은 비어 있고, 비어 있으면 지금 동작과 같다.
- 목록에 있는 봇(자기 자신 포함)의 메시지는 사람 메시지와 같은 필터를 거친다. 스레드 안에서는 봇 멘션이 있어야 하고, 이슈 채널은 최상위 새 글만, 그 밖의 채널은 멘션이 있어야 한다. 시스템 메시지 제외(type 0·19만)도 그대로다.
- 목록에 없는 봇의 메시지는 지금처럼 무시한다.
- 값은 숫자 user ID만 받는다. 숫자가 아니면 데몬 시작 시 Config 오류로 거부한다(별칭 해석 없음 — `channels` 별칭은 채널용이다).
- stdin JSON 계약은 바뀌지 않는다. `author.bot`이 `true`인 이벤트가 발행될 수 있다는 점만 달라진다.
- 문서에 루프 위험과 안전 조건을 적는다. 런처가 결과를 스레드 안에 멘션 없이 올리면 스레드 규칙 때문에 재발행되지 않는다. 이슈 채널 최상위에 봇이 글을 올리면 다시 트리거된다.

## 버린 선택지

- 테스트 전용 합성 이벤트 명령(`daemon emit` 등): 실제 게이트웨이 수신 경로가 검증되지 않는다.
- 봇 메시지 전부 허용: 다른 봇·웹훅이 Claude 실행을 일으킬 수 있다.
- 사람이 직접 트리거 올리기: 사용자가 자동화를 원했다.
- 버튼 클릭 자동화: Discord에 봇이 버튼을 누르는 API가 없다. `AskUserQuestion` 응답 단계는 사람이 누른다.
