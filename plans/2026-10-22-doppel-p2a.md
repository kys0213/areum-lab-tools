# doppel P2a — 프로젝트·카드·배정·세션 실행

> **Plan — 이 시점의 결정 기록.** 현재 정책의 신뢰 소스가 아니다.
> 날짜: 2026-10-22 · 브랜치: epic/doppel · 이슈: 없음 · 승인 출처: 사용자 승인 (전체 설계 `kys0213/kys-claude-plugin` `plans/2026-10-21-doppel.md` 의 결정 17, 진행은 "응")

## 왜

doppel 이 외부 작업을 받아 프로젝트에 배정하고 Claude 세션을 띄워 처리하게 한다. 배정은 판단이라 원장에 쌓아 나중에 모델 제안(P2b)의 판례로 쓴다.

## 범위

- 프로젝트 등록(이름·로컬 경로·설명), 카드 수신·배정·실행·되돌리기·완료, 칸반 UI.
- 사람이 한 배정을 원장에 `kind: triage` 로 기록.
- 세션 실행기: `--launch-command` 를 프로젝트 경로에서 띄우고 stream-json 으로 첫 메시지를 보낸 뒤 결과를 받아 카드를 옮긴다.

## 결정 사항

- **스키마 이관을 들인다.** `decisions.kind` 의 CHECK 에 `triage` 를 더해야 하는데 SQLite 는 CHECK 를 바꿀 수 없어 테이블을 다시 만든다. `PRAGMA user_version` 으로 버전을 두고 열 때 한 번 이관한다. 앞으로의 스키마 변경도 같은 길로 간다.
- **카드 명령은 데몬을 거친다.** 실행기와 UI 알림이 데몬에 있어서, CLI 가 DB 를 직접 쓰면 UI 가 늦게 알고 실행 상태와 어긋난다.
- **stdin 을 열어 두는 동안만 세션이 산다.** 결과마다 보류된 질문이 남았는지 보고, 없으면 stdin 을 닫는다 — 늦은 답은 받되 끝난 세션이 쌓이지 않게.
- **실패는 상태가 아니다** (kanban 원칙을 가져옴). 결과 없이 끝난 카드는 `triaged` 로 되돌리고 `last_error` 에 이유를 남긴다.
- **데몬이 멈추면 실행 중 카드는 다음 시작 때 `triaged` 로 되돌린다.** 데몬이 띄운 세션은 데몬과 함께 끝나기(`kill_on_drop`) 때문이다.
- **동시 실행 상한**은 데몬 인자(`--max-running`, 기본 2)이고, 넘으면 `conflict` 로 거부한다.

## 버린 선택지

- **CHECK 없이 `kind` 를 자유 문자열로** — 원장의 불변식을 DB 에 새긴다는 원칙과 어긋난다.
- **카드 CLI 가 DB 를 직접** — 위 이유.
- **세션을 결과 뒤에도 계속 살려 두기** — 프로세스가 쌓인다. 다시 시키는 것은 `release` 후 `dispatch` (P2b 에서 `--resume`).

## 범위 밖 (P2b)

모델의 배정 제안과 그 판례 검색, opt-in 자동 배정·자동 실행, `--resume` 으로 이어서 시키기.
