# doppel P1a — 데몬·세션 연결·질문 경주·inbox

> **Plan — 이 시점의 결정 기록.** 현재 정책의 신뢰 소스가 아니다.
> 날짜: 2026-10-21 · 브랜치: epic/doppel · 이슈: 없음 · 승인 출처: 사용자 승인 (전체 설계 `kys0213/kys-claude-plugin` `plans/2026-10-21-doppel.md` 의 결정 4·6·13·14·18, 진행은 "자율주행해줘")

## 왜

P0 의 판단 원장은 과거 기록만 읽는다. P1a 는 지금 돌고 있는 세션을 doppel 에 붙여, 세션 상태를 한곳에서 보고 질문·권한 확인을 doppel UI 에서도 답할 수 있게 한다. 브리프(판례 기반 추천)와 수락률은 P1b 다.

## 범위

- 데몬: `doppel daemon run|start|stop|status`, Unix socket + loopback TCP 에 같은 라우터 (`docs/doppel-protocol.md §6`).
- 세션 상태: 이벤트로 사실을 쌓고, 상태는 읽을 때 순수 함수로 판정한다 (`docs/doppel.md §5`).
- ask: 열기·대기·답·보류·확정, 확정 시 판단 원장 기록.
- `doppel attach`, `doppel ask wait|list|answer`, `doppel session list`.
- 웹 UI: 세션 목록과 질문 inbox 한 페이지, `/v1/ui` WebSocket 으로 갱신.
- plugin (`kys-claude-plugin/plugins/doppel`): 세션 이벤트, attach, `AskUserQuestion`·권한 경주, 보류·늦은 답.

## 런타임 확인 (2026-10-21, headless)

`docs/doppel-protocol.md §5` 에 남겼다. 질문 경주, 권한 허용 재호출, 세션 수명 자식 프로세스, Unix socket fetch, idle 세션 `$.prompt.submit` 이 모두 동작했다.

## 결정 사항

- **pidfile 대신 소켓이 단일 실행 잠금이다.** 연결되는 소켓이면 이미 떠 있고, 거부되는 소켓 파일은 잔해라 지운다. 종료는 `/v1/shutdown`. discord 데몬의 pidfile·`kill(2)` 처리가 필요 없어 `libc` 에 의존하지 않는다.
- **세션 상태는 저장하지 않고 판정한다.** 저장하는 것은 사실(턴 진행 여부, 마지막 이벤트 시각, 연속 실패 수, 종료 여부, 마지막 heartbeat)이고, 상태는 `derive_state(facts, open_asks, now, thresholds)` 로 그때그때 낸다. 기준값을 바꾸면 과거 세션도 새 기준으로 보인다.
- **판정 시각은 doppel 의 시계다.** 이벤트의 `at` 은 참고만 한다.
- **hook 의 대기는 `doppel ask wait` (`$.process.run`)로 한다.** `$.http.fetch` 의 시간 제한이 문서에 없어서, 10분까지 기다리는 것이 확인된 수단을 쓴다.
- **ask 확정은 hook 의 `close` 다.** doppel 이 답한 직후 터미널이 이기는 경우를 덮기 위해, doppel 의 `answer` 는 `answered` 까지만 간다.
- **원장 기록 키는 transcript ingest 와 같다** (`source: session`). 나중에 ingest 해도 중복이 생기지 않는다.
- **UI 보호**: loopback 만 열고 `Host` 검사, `POST` 는 `Origin` 검사 + `X-Doppel-Client` 헤더 요구. 커스텀 헤더가 있으면 교차 출처 요청은 preflight 를 거치는데 doppel 은 CORS 를 허용하지 않는다.
- 의존성: `axum`(ws) — HTTP·WebSocket 서버를 Unix socket 과 TCP 에 같은 라우터로 연다. `tokio-tungstenite` — `doppel attach` 의 클라이언트. 워크스페이스 의존성에 더한다.

## 버린 선택지

- **pidfile + `kill(2)`** — 소켓이 이미 단일 실행을 보장하고, Windows 로 넓힐 때 Unix 시그널에 묶이지 않는다.
- **세션 상태를 이벤트마다 갱신해 저장** — 기준값이 바뀌면 저장된 상태가 틀어지고, 정체·끊김처럼 "아무 일도 없음" 으로 생기는 상태는 이벤트가 없어 갱신할 계기가 없다.
- **UI 도 Unix socket 으로** — 브라우저가 Unix socket 에 붙지 못한다.
- **hook 이 `$.http.fetch` long-poll 로 대기** — 시간 제한 계약이 확인되지 않았다.

## 범위 밖 (P1b)

브리프 agent 실행, 판례 검색 번들을 inbox 에 붙이기, 수락률, doppel 이 headless 세션을 띄우는 런처와 `--resume`.
