# doppel P2b — 배정 제안·자동 처리·이어서 시키기

> **Plan — 이 시점의 결정 기록.** 현재 정책의 신뢰 소스가 아니다.
> 날짜: 2026-10-22 · 브랜치: epic/doppel · 이슈: 없음 · 승인 출처: 사용자 승인 (P2a 보고 뒤 다음 단계로 P2b 를 제시, "이어서 가줘")

## 왜

P2a 에서 배정은 전부 사람이 했다. 브리프가 질문에 판례 기반 추천을 붙이듯, 들어온 카드에도
판례 기반 배정 제안을 붙여 사람이 한 번에 확정하게 한다. 제안이 충분히 맞는 게 측정되면
사람이 켠 경우에만 doppel 이 배정·실행까지 한다. 결과가 마음에 안 들면 같은 세션에 피드백을
주고 이어서 시킨다.

## 범위

- **배정 제안**: 카드가 `inbox` 에 들어오면(데몬 `--propose`) 번들(카드·프로젝트 목록·`triage`
  카테고리의 확정 판례)을 명령(기본 `claude -p --output-format json --model sonnet
  /doppel:triage`)에 넘겨 `{ project, priority, confidence, rationale, cited }` 를 받는다.
  plugin 에 `triage` skill 을 더한다. `card propose` 로 다시 요청할 수 있다.
- **평가**: 사람이 처음 배정할 때 제안과 같으면(프로젝트·우선순위 모두) 수락. `stats` 에 배정
  제안 수락률을 더한다.
- **판례 흐름**: 사람의 배정은 원장에 들어올 때 `triage` 카테고리로 분류된다(그 카테고리가
  있을 때). 제안을 뒤집은 배정은 골든 후보(`reason: override`)가 되어 `review` 맨 앞에 온다.
- **자동 배정 (opt-in)**: `--auto-triage` 가 켜져 있고, 지금까지 판정된 제안이
  `--auto-triage-min-judged`(기본 20) 개 이상, 수락률이 `--auto-triage-min-acceptance`(기본
  0.9) 이상이고, 이번 제안의 확신도가 `high` 이며 프로젝트가 있으면 doppel 이 `by: model` 로
  배정한다. 원장에는 넣지 않는다(모델의 답을 판례로 먹이지 않는다).
- **자동 실행 (opt-in)**: `--auto-dispatch` 가 켜져 있으면 `triaged` 이고 `last_error` 가 없는
  (한 번도 되돌려지지 않은) 카드를 우선순위·오래된 순으로 `--max-running` 까지 띄운다. 카드가
  배정될 때, 실행이 끝날 때, 데몬이 시작할 때 다시 본다.
- **이어서 시키기**: `card dispatch <id> --resume [--note "..."]` 는 지난 실행의 세션을
  `--resume <session_id>` 로 이어 띄우고, `--note`(없으면 되돌린 이유)를 첫 메시지로 보낸다.

## 결정 사항

- **제안은 브리프와 같은 틀을 쓴다.** 명령 실행·출력 봉투 해석(`claude -p` 의 `result`, 코드
  펜스 한 겹)은 공용 모듈로 꺼내고, 계약 검증은 각자 한다.
- **수락은 "사람의 첫 배정" 하나로 판정한다.** 이후 재배정은 제안 평가가 아니다. 제안을 다시
  요청하면 그 제안이 판정 대상이 된다.
- **자동 배정 문턱은 데몬 인자다.** 데몬은 측정값과 인자를 비교만 한다(같은 측정값·같은 인자면
  같은 판정). 문턱을 스스로 조정하지 않는다.
- **자동 배정은 원장에 남기지 않는다.** 원칙 2(사람이 손댄 것만 정답) 그대로. 사람이 나중에
  다시 배정하면 그것이 원장에 남는다.
- **자동 실행은 되돌려진 카드를 다시 띄우지 않는다.** 사람이 멈춘 카드가 곧바로 다시 도는 것을
  막는다 — 기준은 `last_error IS NULL`.
- **배정 판단의 카테고리는 확정적으로 정한다.** 종류가 `triage` 면 카테고리도 `triage` 다(원칙
  3). `category_by` 는 `human` — 모델의 분류가 아니다.

## 버린 선택지

- **원장의 모든 배정을 판례로 바로 쓰기** — 리뷰를 거치지 않은 행이 판례가 되면 골든셋 원칙이
  깨진다. 대신 뒤집힌 제안만 후보로 올려 리뷰 부담을 작게 둔다(맞춘 제안은 이미 아는 것).
- **모든 사람 배정을 후보로** — 리뷰 큐가 배정으로 넘친다.
- **자동 실행 시 우선순위 상한 인자** — 지금은 필요 근거가 없다. 켜고 끄는 것만 둔다.
- **이어서 시키기 시 새 세션에 지난 outcome 을 붙여 보내기** — 세션 맥락(읽은 파일·대화)이
  사라진다. `--resume` 이 맥락을 그대로 잇는다.

## 범위 밖

외부 소스(GitHub 이슈·메일) 수신 connector, 카드 간 의존, 자동 실행의 시간대 제한.
